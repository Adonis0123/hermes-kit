# 昨日工作复盘（确认后才改）

owner 要求：定时复盘 **只总结 + 建议**，**等确认** 再自我改进或改 skill。

本机细节：若 `references/local-*.md` 存在，先读它（真实 cron job id、本机相关 skill 路由）。下文 `<job_id>` 指本复盘 cron 的 job id（没有 local 文件时用 `cronjob action=list` 按任务名查）。

## 触发

- 每日 **09:20（Asia/Shanghai 上午）** cron（job `<job_id>`，表达式 **`20 9 * * *`**）
- 用户说「复盘昨天 / 昨天做了什么 / 昨天有哪些可以改进」

### 时间口径（硬，2026-08-02 已改）

| 说法 | 真值 |
|------|------|
| 任务名「昨日工作复盘 09:20」 / `20 9 * * *` | 每天上午 **09:20**（当前正式配置） |
| 复盘范围 | 前一完整自然日 **00:00:00–23:59:59**（Asia/Shanghai） |
| 禁止混入 | 今天尚未完成的工作、前天及更早内容 |
| 当天 09:20 后才建 / 修改 | 首次自动执行在次日 09:20；需要补跑可 `cronjob action=run` |
| `last_run_at=null` + executions 空 | 从未执行，不是「静默成功」 |

### 建 / 改 cron 硬步骤

1. 口语 → 24 小时 cron（上午 9:20 → `20 9 * * *`）
2. **回显**：表达式 + `next_run_at` / 人话时间
3. owner 明确要求修改时直接执行；否则先确认
4. `cronjob action=list` 复核 `schedule` / `next_run_at` / 任务名 / attached skill

排障：`cronjob action=list` + `~/.hermes/cron/jobs.json` + `executions.db`；ticker 正常 ≠ 任务已跑过。详见 `hermes-local-ops` → `references/cron-schedule-echo.md`（`hermes-local-ops` 是可选的本机运维 skill；没装就跳过这些指针）。

## 取证要求

1. 用 `session_search` 浏览昨天的相关会话；必要时读取多个会话终稿。读整个会话只传 `session_id`；`around_message_id` 是全库全局 id，只能填搜索/读取结果里出现过的 id，**禁止猜 `1` 当"从头"**（2026-09-23：9 个会话并发传 1 全部报错，触发 cron 硬停）。
2. 只把真实完成并有消息、文件、测试或外部状态支撑的内容写成结果。
3. 计划、推断和未验收状态必须明确标注，禁止写成已完成。
4. 改进建议最多 5 条；没有值得改的内容就不硬凑。每条必须写「改哪条已有 skill / 为何不新建」。写「新建 xxx」须说明现有哪几条合不进去。禁止默认 `skill_manage create`。细则 `hermes-local-ops` → `skill-admission.md`。
5. **MEMORY.md / USER.md 不是昨日证据（硬·v0.20.5）**：cron 现会注入热层记忆。复盘「昨天做了什么」**只认** `session_search` / cron output / 文件或外部状态；禁止用 MEMORY 条目当完成证明，禁止用记忆工具改 MEMORY。热层规则最多当「落点建议」的标签。

## 硬规则

| 做 | 禁 |
|----|----|
| 汇总昨日事项、结果与证据 | 在 cron 会话内自动改 skill / memory / 代码 / 配置 |
| 列改进建议并标落点 | 凭 MEMORY.md / USER.md / 热层记忆编造工作或结果 |
| 建议默认「改哪条已有 skill」 | 默认「新建 xxx」或 `skill_manage create` |
| 等「确认 1,3」「按推荐来」 | 未确认先执行建议 |

用户明确确认某条后，再由当前交互会话执行对应 skill / memory / 流程改动。

## 确认语解析（硬）

| 用户说法 | 含义 |
|----------|------|
| `确认 1,3` / `确认 1` / `确认 2,4` | 只做**最新复盘编号表**对应项 |
| **`只优化 N`** / `只优化 1,3` | 等价 `确认 N`：只做**磁盘最新** `<job_id>/*.md` 的第 N 条；其余不动。**不是**升版后「值得关注」编号、不是长会话自拟清单 |
| `确认，按你推荐的来` / `按推荐来` / `按推荐的来` / **`全部优化`** | 做最新复盘里的全部建议项（除非明确跳过） |
| `全部跳过` | 零改动，短回即可 |
| `改一下第 N 条：…` | 按改写后的 N 执行，其余未点名不动 |
| **其他会话裸数字**（`1、3、4` / `1 2`，无「确认」/「优化」） | **不当复盘确认**。可能是当前会话自己的选项编号 |

## 跨会话确认（硬）

复盘由 cron 投递到 home；owner 可能在新 DM 会话回复确认。

0. **执行前强制读磁盘最新表（硬·2026-08-27；补·2026-09-09/11）**：确认语进来 **第一件事只读** `ls -t ~/.hermes/cron/output/<job_id>/*.md | head -1`，读完 `### 可以改进` **再动手**。压缩窗口后：**只认磁盘最新表 + 压缩后那条用户原文**。禁止执行摘要里的旧「按照推荐来」/「确认 1,2」/「锁屏」。课例 2026-09-08：先按旧确认 1,2 改了一轮。课例 2026-09-10：「只优化 2」压缩后先回放 9/9 表和晚上「锁屏」。
1. **先定位最新复盘终稿**，不要猜建议内容：
   - `session_search` query：`昨日工作复盘` / `cron_<job_id>`
   - 优先读取 session_id 形如 `cron_<job_id>_*` 的最后一条 assistant
   - **FTS 找不到 / 只命中旧会话 / 标题对不上当天（硬·2026-08-20）**：同上，读 cron output **最新** `*.md`。`session_search` 与磁盘文件日期不一致时，**以磁盘 `ls -t` 为准**。
2. 解析**该编号表**，再按确认语执行。数字「1 2 3」只对**这份表**，不对长会话旧清单。
   - **只认**带「确认」的回复（`确认 1,3` / `确认 1`）、`只优化 N`、复盘会话本身的跟进、或「按推荐来 / 全部优化」。
   - **其他会话裸数字不当复盘确认**（硬·2026-08-25）：09:25「1、3、4」落在卡片流式会话，不是 8/24 复盘 1–4。两套编号间隔几分钟也要停问或先对表，禁止当复盘执行。
3. 执行顺序：skill 补丁 → 同 skill/reference 扫旧口径 → memory（仅建议明确需要且通过写入闸）→ 验证。
4. 执行完用短表回执：编号 / 落点 / 验证 / 是否需 `/restart`；不要重贴整份复盘。
5. 找不到最新复盘时，直说缺源并请用户贴编号或 `@session:…`；**禁止**用当前长会话可复用项顶替；禁止凭记忆编造。

## 输出结构（中文、短）

### 昨日做了什么

表：事项 / 结果 / 证据或会话

### 可以改进

编号表：问题 / 根因 / 建议 / 落点 / 改哪条已有（或为何不新建）

失败课例默认 patch 已有 skill；合不进去才允许新建。

### 待你确认

示例：`确认 1,3` / `按推荐来` / `全部跳过`

昨日无显著工作：明确写「昨日无显著工作」，只给 0–2 条轻量观察。
